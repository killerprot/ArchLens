# PRD: ArchLens (рабочее название)

GUI-инструмент для Arch Linux, который объясняет, что занимает место в системе, почему пакет вообще установлен и что можно безопасно удалить.

- **Статус:** черновик v0.1
- **Автор:** Кирилл
- **Платформа:** Arch Linux и производные (Manjaro, EndeavourOS, CachyOS)
- **Стек:** Python 3.11+, PySide6

---

## 1. Проблема

Со временем Arch-система обрастает пакетами. Пользователь, который ставил и удалял программы годами, не может быстро ответить на вопросы:

1. Почему этот пакет у меня стоит? Кто его потащил?
2. Сколько места я реально освобожу, если его удалю?
3. Какие пакеты осиротели (orphans) и что из них точно можно убирать?
4. Что раздувает систему: пакеты, кэш или AUR-сборки?

Сейчас для этого нужна связка `pacman -Qi`, `-Qe`, `-Qdt`, `pactree`, `expac` и ручной разбор вывода. Готового графического инструмента, который объясняет *причины*, а не просто показывает список, нет.

## 2. Целевая аудитория

| Сегмент | Что нужно |
|---|---|
| Пользователи Arch средней опытности | Навести порядок без риска сломать систему |
| Новички на Arch-производных (Manjaro, EndeavourOS) | Понятный интерфейс вместо набора команд |
| Энтузиасты, которые любят «чистую» систему | Точная аналитика по размеру и зависимостям |

## 3. Цели и не-цели

### Цели (MVP)
- Показать все установленные пакеты с размером и причиной установки (явно / как зависимость).
- Для любого пакета показать цепочку «кто его требует» до явно установленных пакетов.
- Посчитать «освободится при удалении»: размер пакета плюс зависимости, которые уйдут вместе с ним.
- Найти сирот и показать суммарный размер.
- Показать размер кэша pacman и подсказать, что можно очистить.
- Дать удалить выбранное безопасно: сначала предпросмотр, потом подтверждение.

### Не-цели (по крайней мере для v1)
- Не замена pacman и не полноценный менеджер установки (wyay остаётся отдельным проектом).
- Не поддержка не-Arch дистрибутивов.
- Не автоматическая «умная» чистка без участия пользователя.
- Не GUI для обновлений системы.

## 4. Пользовательские сценарии

1. **«Что тут тяжёлое?»** Я открываю приложение, сортирую по размеру и вижу топ пакетов. Рядом подпись: «освободится 1.2 ГБ».
2. **«Откуда это взялось?»** Я нажимаю на незнакомый пакет и вижу цепочку `firefox → gtk3 → at-spi2-core → ...`.
3. **«Хочу убрать мусор».** Я открываю вкладку «Сироты», вижу список с общим размером, отмечаю нужное и жму «Удалить». Перед удалением вижу точный список из `pacman`, и только после подтверждения запускается удаление.
4. **«Кэш разросся».** Я вижу размер кэша по версиям пакетов и очищаю всё, кроме последних N версий.
5. **«Это моя вещь, не трогать».** Я помечаю пакет «защищённым», и приложение больше не предлагает его удалить.

## 5. Функциональные требования

### P0 (MVP)
| ID | Требование |
|---|---|
| F1 | Читать локальную базу pacman без прав root и строить список пакетов (имя, версия, описание, размер, причина установки, дата установки) |
| F2 | Таблица пакетов с поиском, сортировкой и фильтрами (явные / зависимости / сироты / AUR и прочие чужие) |
| F3 | Карточка пакета: метаданные, прямые зависимости, обратные зависимости (кто требует) |
| F4 | «Почему установлен»: кратчайшая цепочка до явно установленного пакета |
| F5 | Расчёт «освободится при удалении» через замыкание удаления (`-Rns`-эквивалент) |
| F6 | Вкладка «Сироты» с суммарным размером |
| F7 | Удаление через `pkexec`/polkit с обязательным предпросмотром (dry-run) и подтверждением |
| F8 | Вкладка «Кэш»: размер `/var/cache/pacman/pkg`, группировка по пакетам, очистка старых версий |

### P1
| ID | Требование |
|---|---|
| F9 | Визуализация размера (treemap) по пакетам и группам |
| F10 | Список защищённых пакетов (хранится в конфиге пользователя) |
| F11 | Опциональные зависимости (optdepends): какие стоят, какие нет |
| F12 | Экспорт отчёта (Markdown или JSON) |

### P2
| ID | Требование |
|---|---|
| F13 | Граф зависимостей (интерактивный) |
| F14 | История: как менялся размер системы (на основе `pacman.log`) |
| F15 | Пакет в AUR для установки самого приложения |

## 6. Нефункциональные требования

| Область | Требование |
|---|---|
| Производительность | Холодная загрузка базы из ~1500 пакетов не дольше 2 секунд; интерфейс не зависает ни при каком анализе (всё тяжёлое в фоне) |
| Безопасность | Чтение только из локальной базы; любые изменяющие действия только через pacman и polkit, никогда напрямую |
| Надёжность | Приложение не должно удалять ничего без явного подтверждения пользователя после предпросмотра |
| Совместимость | Arch и производные; Wayland и X11; Qt 6 |
| Тестируемость | Логика анализа отделена от GUI и тестируется на фикстурах без реальной системы |

## 7. Метрики успеха

Для личного проекта они простые:

- MVP работает на моей собственной системе и находит реальный мусор, который я до этого не замечал.
- Расчёт «освободится при удалении» совпадает с тем, что показывает `pacman -Rns --print` (сверка на 20+ пакетах).
- Хотя бы 3 сторонних пользователя Arch попробовали и дали обратную связь.
- Репозиторий с README, скриншотами и релизом (пригодно для портфолио).
- Опционально: звёзды на GitHub, установки из AUR.

## 8. Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| Пользователь удалит нужное | Средняя | Обязательный dry-run, защищённые пакеты, список базовых пакетов блокируется по умолчанию |
| Неточность расчёта «освободится» из-за `provides`, виртуальных пакетов и версионных ограничений | Высокая | Использовать `pacman` dry-run как источник истины, собственный расчёт только для быстрой оценки |
| Расхождение формата локальной базы между версиями pacman | Низкая | Закрепить поведение тестами, при возможности использовать `pyalpm` |
| Уже существуют похожие инструменты (pacman-контейнеры, `pacseek`, `octopi`) | Средняя | Сделать упор на объяснение причин и размеры «с учётом зависимостей» |
| Потеря интереса | Средняя | Маленький MVP: сначала F1–F4, остальное по мере желания |
