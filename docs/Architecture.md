# Architecture: ArchLens (рабочее название)

Документ описывает техническое устройство MVP из `PRD.md`.

---

## 1. Ключевые решения

| # | Решение | Обоснование |
|---|---|---|
| D1 | Python 3.11+ и PySide6 | Знакомый стек, опыт из wyay, быстрая разработка |
| D2 | Чтение данных из локальной базы pacman (`/var/lib/pacman/local`) | Не нужен root, нет зависимости от формата вывода CLI, быстро |
| D3 | Собственный граф зависимостей в памяти для аналитики | Мгновенные запросы «кто требует», «что освободится» |
| D4 | `pacman` dry-run как источник истины для удаления | Свой расчёт может ошибаться на `provides` и версиях; перед удалением всегда сверяемся с pacman |
| D5 | Удаление только через `pkexec pacman` | Права получает polkit, приложение само не работает от root |
| D6 | Слоистая архитектура: core не знает про Qt | Логику можно тестировать без GUI |
| D7 | Тяжёлая работа в фоне (`QThreadPool`) | Интерфейс не подвисает |

Вопрос про `pyalpm` и прямой разбор остаётся открытым. Для MVP выбираем **прямой разбор** файлов `desc` и `depends`: формат простой, зависимость не нужна. Если появятся проблемы с `provides` и версиями, подключаем `pyalpm` через тот же интерфейс `PackageSource`.

## 4. Модель данных

```python
@dataclass(frozen=True)
class Package:
    name: str
    version: str
    description: str
    installed_size: int          # байты, поле %SIZE%
    reason: Reason               # EXPLICIT | DEPENDENCY
    install_date: datetime
    depends: tuple[str, ...]     # строки как в базе: "glibc>=2.38", "sh"
    optdepends: tuple[str, ...]
    provides: tuple[str, ...]
    is_foreign: bool             # AUR или чужой репозиторий
```

Из локальной базы берутся файлы `desc` (метаданные, `%REASON%`, `%SIZE%`, `%INSTALLDATE%`) и `depends` (`%DEPENDS%`, `%OPTDEPENDS%`, `%PROVIDES%`).

Признак `is_foreign` получаем так: сверяем со списком пакетов из синхронизированных баз `/var/lib/pacman/sync`. Если имени там нет, пакет чужой.

## 5. Граф зависимостей

`DependencyGraph` строится один раз при загрузке и хранит:

- `by_name: dict[str, Package]`
- `providers: dict[str, set[str]]`: виртуальное имя → кто его обеспечивает (учитывает `provides`)
- `deps: dict[str, set[str]]`: пакет → от каких пакетов он зависит (после разрешения имён)
- `rdeps: dict[str, set[str]]`: обратные рёбра

### Разрешение зависимости
Строка `"libfoo.so=1-64"` или `"sh"` или `"glibc>=2.38"` разбирается на имя и ограничение. Имя ищется сначала среди реальных пакетов, потом в `providers`. Версионные ограничения в MVP игнорируются: в уже установленной и согласованной pacman'ом системе они выполнены.

### Основные алгоритмы

| Функция | Что делает | Сложность |
|---|---|---|
| `orphans()` | Пакеты с `reason=DEPENDENCY`, у которых нет обратных зависимостей среди установленных | O(V+E) |
| `explain_why(pkg)` | BFS по `rdeps` до ближайшего явно установленного пакета; возвращает цепочку | O(V+E) |
| `removal_closure(pkgs)` | Что удалится вместе с набором: сам набор плюс зависимости, которые после удаления станут не нужны (аналог `-Rns`) | O(V+E) |
| `freed_size(pkgs)` | Сумма `installed_size` по `removal_closure` | O(V) |

### Замыкание удаления

Идея алгоритма:

1. Берём множество `R` = выбранные пакеты.
2. Для каждой зависимости `d` удаляемого пакета: если `d` не явно установлен и все его обратные зависимости лежат внутри `R`, то добавляем `d` в `R`.
3. Повторяем, пока множество растёт.

Пакеты с `reason=EXPLICIT` никогда не добавляются автоматически (так же поступает `pacman -Rns`).

Если проверка показывает, что какой-то пакет вне `R` требует удаляемый, операция помечается **заблокированной**: показываем кто мешает.

## 6. Удаление и безопасность

Поток удаления:

```
пользователь выбирает пакеты
        │
        ▼
core.removal_closure()  ← быстрая оценка для UI
        │
        ▼
pacman_cli.dry_run()    ← pacman -Rns --print <pkgs>   (источник истины)
        │
        ▼
сравнение: свой расчёт vs pacman
        │   расхождение → предупреждение в диалоге
        ▼
confirm_dialog: точный список и размер
        │  подтверждение
        ▼
pkexec pacman -Rns --noconfirm <pkgs>
        │
        ▼
перезагрузка базы и обновление UI
```

Правила безопасности:

1. Приложение никогда не запускается от root. Только дочерний процесс через `pkexec`.
2. Удаление невозможно без предварительного dry-run и явного подтверждения.
3. Список пакетов передаётся списком аргументов, а не строкой для shell (`subprocess.run([...])`, без `shell=True`).
4. Защищённые пакеты (`base`, `linux`, `pacman`, `systemd`, `glibc` и т. д. плюс пользовательский список) нельзя выбрать для удаления.
5. Если dry-run вернул ошибку, удаление отменяется.

> Проверить на практике: точный набор флагов dry-run (`-p` / `--print`) и поведение без root.

## 7. Кэш

`cache_fs.py` обходит `/var/cache/pacman/pkg`, разбирает имена файлов вида `имя-версия-релиз-арх.pkg.tar.zst`, группирует по пакету и считает размер.

Очистка делается через `paccache` (пакет `pacman-contrib`), если он установлен: `pkexec paccache -rk<N>`. Если нет, показываем подсказку, как установить. Так мы не изобретаем логику выбора версий.

## 8. GUI

- **Главное окно:** вкладки «Пакеты», «Сироты», «Кэш», справа или снизу карточка выбранного пакета.
- **Таблица пакетов:** `QAbstractTableModel` над списком `Package` + `QSortFilterProxyModel` для поиска и фильтров. Колонки: имя, версия, размер, «освободится», причина, дата.
- **Карточка:** метаданные, списки зависимостей и обратных зависимостей (клик ведёт к соседнему пакету), цепочка «почему установлен».
- **Диалог удаления:** список из dry-run, суммарный размер, предупреждение при расхождении.

### Потоки

| Задача | Где выполняется |
|---|---|
| Загрузка и разбор базы | `QThreadPool` + сигнал `loaded(graph)` |
| Расчёт «освободится» для всех пакетов | Фон; считается лениво для видимых строк, остальное кэшируется |
| Dry-run и удаление | Фон; вывод идёт в диалог |
| Обход кэша | Фон |

Core работает с неизменяемыми данными после загрузки, поэтому блокировки не нужны: при перезагрузке базы строится новый граф и заменяет старый целиком.

## 10. Тестирование

| Уровень | Что проверяем | Как |
|---|---|---|
| Unit | Разбор `desc` и `depends`, граф, `removal_closure`, `explain_why` | Искусственная база в `tests/fixtures/fake_pacman_db/` |
| Сверка | Расчёт против `pacman -Rns --print` | Ручной скрипт на реальной системе, 20+ пакетов |
| UI | Загрузка и смена вкладок | `pytest-qt` на фикстурной базе |
| Безопасность | Невозможно вызвать удаление без dry-run; защищённые пакеты блокируются | Unit-тесты на контроллер |

Фикстурная база должна включать краевые случаи: виртуальные пакеты (`provides`), циклические зависимости, пакет с несколькими провайдерами, сироту, цепочку из трёх уровней.

## 11. Упаковка

1. `pyproject.toml` + запуск через `python -m archlens`.
2. `PKGBUILD` для AUR (`archlens-git`, позже `archlens`).
3. `.desktop`-файл и иконка.
4. Зависимости пакета: `python`, `pyside6`; опционально `pacman-contrib`.

## 12. Расширение

- **Treemap:** отдельный виджет поверх тех же данных `Package.installed_size`.
- **История размера:** парсер `pacman.log` как ещё один источник в `infra/`.
- **Другие менеджеры:** интерфейс `PackageSource` позволит позже подключить Flatpak.
- **Интеграция с wyay:** общий пакет `core` или два режима в одном приложении.

## 13. Известные ограничения MVP

- Версионные ограничения зависимостей не проверяются.
- Не учитываются зависимости времени сборки (`makedepends`) для AUR-пакетов, которых нет в локальной базе.
- Размер считается по `%SIZE%` из базы (установленный размер), а не по реальной занятости диска с учётом жёстких ссылок и сжатия файловой системы.
